# sky-audit

Можно ли верить прогнозу погоды? Проект каждый час собирает прогнозы и фактическую погоду для 12 столиц, хранит историю и показывает, насколько ошибается прогноз в зависимости от города и того, на сколько часов или дней вперёд он сделан.

Весь пайплайн поднимается одной командой в Docker Compose и дальше работает без ручного участия: сам собирает данные, проверяет их качество и пересобирает витрины.

## Архитектура

```
Open-Meteo API
      |
      v
Airflow DAG weather_fetch_to_kafka (раз в час)
  1. load_raw_data_to_minio       -> сырой ответ API в MinIO (S3)
  2. get_from_minio_and_producer  -> прогнозы и факт в два топика Kafka
      |
      v
Kafka: topic_forecasts, topic_actuals
      |
      v
consumer (отдельный контейнер) -> ClickHouse, слой raw
      |
      v
Airflow DAG dbt_build (раз в час)
  1. dbt source freshness  -> остановка, если данные перестали поступать
  2. dbt build             -> staging -> intermediate -> marts + тесты
```

Справочник городов хранится в PostgreSQL и подключён к ClickHouse через движок PostgreSQL, поэтому dbt может джойнить его с остальными данными.

## Стек

Python, Apache Airflow, Apache Kafka (KRaft), ClickHouse, PostgreSQL, MinIO (S3-совместимое хранилище), dbt (dbt-clickhouse, dbt_utils), Docker Compose.

## Слои данных

| Слой | Модели | Что происходит |
|---|---|---|
| raw | `raw.forecasts`, `raw.actuals`, `raw.cities` | данные в том виде, в каком их записал consumer |
| staging | `stg_forecasts`, `stg_actuals`, `stg_cities` | дедупликация, округление времени факта до часа, расчёт горизонта прогноза |
| intermediate | `interm_forecast_vs_actual` | сопоставление каждого прогноза с фактической погодой и расчёт ошибки |
| marts | `mart_accuracy_by_horizon_hour`, `mart_accuracy_by_horizon_day`, `mart_accuracy_by_city_overall` | MAE и bias по городам и горизонтам прогноза |

**MAE** - средняя абсолютная ошибка: на сколько градусов в среднем промахивается прогноз.
**Bias** - средняя ошибка со знаком: завышает прогноз значения или занижает.

## Надёжность и качество данных

- **Landing zone в MinIO.** Сырой ответ API сохраняется как есть, вместе со временем запроса и списком городов. Если отправка в Kafka упадёт, данные можно переотправить без повторного запроса к API.
- **Ключ файла по логическому времени запуска Airflow.** Обе задачи DAG'а строят одинаковый ключ из `{{ ts_nodash }}`, поэтому повторный запуск того же часа перезаписывает тот же файл, а не создаёт дубль.
- **At-least-once в consumer.** Offset'ы Kafka коммитятся только после успешной вставки в ClickHouse, поэтому при сбое данные не теряются. Возможные дубли убираются на уровне staging.
- **32 теста dbt** на всех слоях: уникальность комбинаций ключей, диапазоны значений, связи между таблицами, отсутствие пустых значений.
- **Source freshness.** Перед пересборкой витрин dbt проверяет, когда в последний раз приходили данные. При задержке больше 2 часов выдаётся предупреждение, больше 3 часов - сборка останавливается.
- **Собственный Docker-образ Airflow.** Зависимости ставятся на этапе сборки, поэтому контейнеры стартуют за секунды, а не устанавливают пакеты при каждом запуске.

## Запуск

Нужен только Docker Desktop.

1. Склонировать репозиторий.
2. Создать файл `.env` по образцу `.env.example` и заполнить пароли.
3. Запустить:

```bash
docker compose up -d --build
```

4. Открыть Airflow и включить оба DAG'а: `weather_fetch_to_kafka` и `dbt_build`.

При первом запуске ClickHouse и PostgreSQL сами создают таблицы и справочник городов из скриптов в папке `init/`, а бакет в MinIO создаётся при первом запуске DAG'а.

| Сервис | Адрес |
|---|---|
| Airflow | http://localhost:8093 |
| Kafka UI | http://localhost:8933 |
| MinIO Console | http://localhost:9001 |
| ClickHouse (HTTP) | localhost:8333 |
| PostgreSQL | localhost:5333 |

## Структура проекта

```
sky-audit/
├── dags/                 # DAG'и Airflow
├── src/                  # сбор данных, работа с MinIO и Kafka
├── consumer_dir/         # consumer Kafka -> ClickHouse и его Dockerfile
├── sky_audit_dbt/        # dbt-проект: модели, тесты, источники
├── init/                 # SQL-скрипты для первого запуска ClickHouse и PostgreSQL
├── Dockerfile            # образ Airflow с dbt и зависимостями
├── docker-compose.yml
└── .env.example
```
